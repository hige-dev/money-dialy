# 家族用GAS家計簿のローカル確認

このディレクトリには、GASバックエンドの模擬サービスを使うOAuth認証・保存・財布・移行確認と、ローカルHTMLを使うPlaywright画面確認があります。Googleアカウント、Googleスプレッドシート、GASデプロイには接続しません。

## 家族用デプロイガード確認

```sh
node scripts/deploy-family-webapp-guard-check.mjs
```

一時エディタ用公開RPCが`Code.gs`または別の`.gs`/`.js`ファイル（サブディレクトリを含む）に残った状態で、デプロイスクリプトがdry-runと通常実行の両方を拒否し、ソースを変更せず、claspを実行しないことを一時ディレクトリ内で確認します。通常時も`Code.gs`と`appsscript.json`の両方がpush結果に含まれる場合だけdeployし、`Skipping push`、更新対象なし、マニフェスト未同期ではdeployしないことを確認します。

## バックエンド確認

Node.js 24で次を実行します。

```sh
node scripts/backend-check.mjs
```

実Google鍵から切り離したテスト用RSA鍵で署名付きIDトークンを作成し、認可URL、State Token、state/nonce、認証コード交換、署名、`iss`・`aud`・期限・確認済みメール、未登録・停止中ユーザー、管理者操作の拒否を確認します。サービス承認確認では全宣言スコープを先に要求し、実行アカウントのメール有無だけを検査します。実行アカウントをログイン認証に使わないこと、一時Script Propertyを保存・読戻し・削除して設定値と台帳を変更しないこと、書込拒否を検知すること、固定段階ログに認証情報や個人情報を含めないことも確認します。模擬スプレッドシートでは初期化の非破壊性、支出の作成・更新・削除、利用者と支払元の別保存、財布の補充・支出計算、補充を支出合計から除外すること、バックアップの可視性・収入フィルターを確認します。

## レスポンシブ画面確認

```sh
node scripts/visual-check.mjs
```

画面確認前の静的検査では`script.storage`と`userinfo.email`の宣言、`requireAllScopes(FULL)`と実行アカウント確認の順序、実行アカウントをユーザー認証に使わないこと、callback段階ログを確認します。Playwright Chromiumを使って320px、390px、480px、768px、1280pxで集計・入力・カレンダー・設定を開き、横はみ出し、480px以下の中央配置、下部ナビ、利用者と支払元の選択、設定表示、JavaScript例外を確認します。前回データの確認では応答を保留し、応答前の即表示と閲覧専用、動的な設定フォームと合成イベント経由の保存停止、確認後の最新値・編集復帰を検証します。通信失敗と再試行、管理者の降格、一般利用者の復元、保存破損・容量不足・保存不可、世代違い・別セッション、新規ログイン、利用停止・失効、起動/再試行中のログアウトと別タブ変更、遅延応答の破棄、初期化待ちと初期化後の通常表示も確認します。画面は`.cache/screenshots/`へ保存します。Linuxの共有ライブラリが不足する場合は `.cache/system-libs/usr/lib/x86_64-linux-gnu/` の既存ライブラリを`LD_LIBRARY_PATH`へ追加します。

ローカル画面は許可リストの模擬ユーザーと模擬データを使い、Google認証リンクのトップレベル遷移と認証後の画面初期化を確認します。Google CloudのOAuth設定、実GASの`/usercallback`、実シート権限、GASデプロイ後のログインは確認しません。
