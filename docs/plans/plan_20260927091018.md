# 計画

## 目標

家族用GAS家計簿のログインを、Google Identity Servicesのブラウザー認証からApps Script内のサーバー側OAuth認証コードフローへ切り替える。管理者のスプレッドシートは共有せず、Googleアカウントを検証して`Users`シートに登録された利用者だけに操作を許可する。

## 現在の調査結果

- `gas/webapp-pilot/Client.html`はGoogle Identity Servicesを使い、ブラウザーから受け取ったIDトークンをGASへ渡す。
- `gas/webapp-pilot/Code.gs`はGoogle公開鍵を使ってIDトークンの署名、発行元、宛先、有効期限、確認済みメールを検証し、各サーバー関数で`Users`シートを照合する。
- HtmlServiceの実行時オリジンは`https://n-qnqdzzj2xxyh5b6yaymjth5krtygzvytiefe2ka-0lu-script.googleusercontent.com`。`script.google.com`とは一致せず、Google Cloudでは実オリジンの登録が許可されない。
- `gas/webapp-pilot/appsscript.json`は`MYSELF`アクセス、`USER_DEPLOYING`実行のまま。家族ユーザーへ公開されていない。
- `gas/webapp-pilot-checks/scripts/backend-check.mjs`は署名、宛先、有効期限、許可ユーザーを検査する。`visual-check.mjs`はローカルの画面・モック操作を確認し、実Googleログインや実GAS通信は行わない。
- Apps Script OAuth2ライブラリは`https://script.google.com/macros/d/{SCRIPT_ID}/usercallback`形式のコールバックを案内し、Googleの認可コード交換サンプルを含む。[ライブラリ](https://github.com/googleworkspace/apps-script-oauth2)、[Google OAuthサーバーフロー](https://developers.google.com/identity/openid-connect/openid-connect)
- GoogleのOAuthポリシーは認証画面のJavaScript生成元に所有または利用許可のあるドメインを求める。[ポリシー](https://developers.google.com/identity/protocols/oauth2/policies)
- 現在のApps Script IDに対するコールバックURIは次のとおり。

  ```text
  https://script.google.com/macros/d/1zhqVIRy5YKrDURd77Tl5I4Za4f-1kvGqyJbvwnesW1HLFt8j7InXa3sQ/usercallback
  ```

## 決定事項

- 利用者の選択により、画面・認証コールバック・データ処理をGAS内に置くサーバー側OAuth方式を採用する。
- 認証コード交換では`openid email`だけを要求し、Google IDトークンを取得する。DriveやSheetsなど利用者のGoogleデータへの追加アクセスは要求しない。
- Apps ScriptのState TokenをOAuthの`state`に使い、認証要求ごとの`nonce`も照合して、偽造・再利用された応答を拒否する。
- 認証コード交換で得たIDトークンは、既存の署名・発行元・宛先・期限・メール確認検証を通した後にだけ`Users`シートと照合する。既存のサーバー関数ごとの認証・権限確認を維持する。
- OAuthクライアントシークレットはApps Scriptのスクリプトプロパティに置き、ソースコード・HTML・ログ・シートに保存しない。利用者がチャットへ貼り付ける必要はない。
- 利用者向け画面は認証コード交換後に表示し、IDトークンは既存どおりブラウザーのメモリー内で扱う。Googleのアクセストークン・更新トークンは保存・利用しない。
- Google CloudでコールバックURIが登録でき、実デプロイでログインを確認するまで、デプロイアクセスを広げない。公開時も`USER_DEPLOYING`を維持し、ログイン必須の`ANYONE`に限定する。

## 解決済みの未決事項

- **認証方式:** ユーザーはA案（GAS内のサーバー側OAuth）を選択した。S3等の管理ドメインへ画面を戻す案は採用しない。

## 対象範囲

- GISのボタンとクライアント側認証初期化を、GASが生成するGoogle認証リンクに置き換える。
- OAuth認可URLの生成、state/nonce作成、Apps Script `/usercallback` の認証コード受け取り、Googleトークンエンドポイントとのコード交換、IDトークン検証を実装する。
- 認証成功後に家計簿画面を表示し、未登録・停止ユーザー、認証拒否、state/nonce不一致、コード交換失敗、署名・宛先・期限不正を日本語で拒否する。
- `README.md`と`docs/gas-family-ledger-migration.md`のログイン設定・公開条件をサーバー側OAuthに合わせる。正確なコールバックURI、スクリプトプロパティ設定、OAuthシークレットの取り扱いを記載する。
- 既存バックエンド検証と画面検証を更新する。
- Apps Script側がコールバックURIを受け付けない、または実デプロイのコールバックを安全に完了できない場合は、ログイン・データアクセスを公開せず、確認結果を報告する。

## 対象外

- 家族用スプレッドシートの共有設定変更。
- Googleユーザーのデータを読む追加スコープ、アクセストークン・更新トークンの永続化。
- OAuthクライアントの新規作成やGoogle Cloudのブランド審査代行。
- `FAMILY_SPREADSHEET_ID`や初期管理者シートの設定。これらは今回の認証方式切替とは別の初期設定として扱う。

## 手順

1. Apps Script用のOAuth設定を追加する。クライアントIDは既存設定を再利用し、クライアントシークレットはスクリプトプロパティから読む。ログイン開始時にState Tokenと一回限りのnonceを生成する。
2. `openid email`を要求する認可URLを作り、HtmlServiceのログイン画面にトップレベルで遷移できるリンクを表示する。
3. `authCallback`をApps Scriptの`/usercallback`へ結び、state検証後に認証コードをサーバー側で交換する。トークン応答からIDトークンだけを取り出し、署名、既存クレーム、nonceを検証する。
4. 検証済みメールを`Users`シートに照合し、許可された利用者だけへアプリ画面を返す。既存の各データAPIにある認証・権限確認を維持する。
5. OAuth設定エラーや拒否を日本語で表示し、ログに認証コード、IDトークン、シークレットを出さない。
6. READMEと移行手順を更新し、Google Cloudに登録するURIとスクリプトプロパティの設定を記す。
7. ローカルテストを追加・実行する。設定済みのクライアントシークレットとCloud設定が使える場合に限り、まず非公開の実デプロイで認証コールバックを確認する。成功後にのみログイン必須アクセスへ切り替え、許可・未許可ユーザーを確認する。

## 検証

- `node gas/webapp-pilot-checks/scripts/backend-check.mjs`でstate/nonce、トークン交換応答、署名・宛先・期限・メール確認、ユーザー許可リスト、管理者権限を確認する。
- `PLAYWRIGHT_BROWSERS_PATH="$PWD/.cache/ms-playwright" node gas/webapp-pilot-checks/scripts/visual-check.mjs`でログインリンク、認証後画面、スマートフォン幅・デスクトップ幅を確認する。
- `git diff --check`を実行する。
- 実GAS確認では、許可された管理者と未登録アカウントでの結果、state/nonce検証、公開アクセス設定を確認する。実GAS OAuthをローカルテストで代替しない。
- コールバックURIまたはクライアントシークレットが未設定なら、実GASの完了確認を保留し、必要な管理者設定と確認できなかった項目を報告する。

## リスク

- Google CloudがApps ScriptのコールバックURIを当該OAuthクライアントに登録できるか、実設定で確認が必要。
- Apps Scriptの`/usercallback`から返すHTMLと認証後画面の連携は、実デプロイで確認が必要。失敗時にメールやIDトークンをURL・ログへ露出する回避策は採用しない。
- アプリURL自体はログイン中のGoogleアカウントへ表示される。許可リスト外の利用者がデータAPIを直接呼んでも、すべてのサーバー関数で拒否されることを維持する。
- クライアントシークレットの設定が完了するまで、家族ユーザー向けアクセスは有効にしない。
